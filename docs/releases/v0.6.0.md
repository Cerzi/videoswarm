## What's new

VideoSwarm 0.6 is a major large-library, review-workflow, fullscreen, and
reliability overhaul for people inspecting large batches of short generated
video clips.

### Large libraries feel dramatically faster

- Folder scans are incremental, cancellable, and report their real phase,
  progress, active path, elapsed time, and working-set memory.
- A persistent SQLite index provides a cached first grid on revisits while an
  authoritative filesystem refresh completes in the background.
- Virtualized masonry, bounded media scheduling, finite native queues, and
  lifecycle-owned caches keep inactive folders from retaining video resources.
- Recursive folder trees, three folder scopes, sibling cycling, pinned roots,
  saved views, and folder grouping make large recursive libraries navigable.

### A complete review workflow

- **Accept**, **Reviewed**, **Reject**, and **Unreviewed** states are distinct
  from tags and ratings.
- `A`/`S`/`D`/`F`, numeric ratings, optional advance-after-marking, stable
  progress, and one-step coupled undo support one-handed review.
- Lightweight saved review positions survive folder changes and application
  restarts through **Find Unreviewed** and **Resume saved view**.
- **Process Results** supports bounded parallel Reject trashing and safe
  **Copy Accepted** with relative-tree preservation, collision preflight,
  cancellation, no-overwrite publication, and optional recognized JSON
  sidecars.

### Fullscreen Review Loupe

- Navigate the complete current collection independently of the mounted grid
  with `Q`/`E` or `←`/`→`.
- Review, rate, tag, inspect metadata, undo, and use safe file utilities without
  leaving fullscreen.
- Session-local mute state, reliable synchronous audio teardown, fitted media,
  accessible modal behavior, and exact action targeting harden repeated review.

### Better metadata and workspace UX

- Selection Details can remain beside the clip as a draggable inspector or
  dock into the two-tab Library/Details workspace.
- Supported embedded ComfyUI/VHS execution graphs expose prompt, negative
  prompt, model, seed, sampler, LoRA, source, and provenance fields without
  retaining raw workflows. Exact adjacent JSON sidecars remain a fallback.
- Audio indicators, richer zoom steps, clearer pinned-root state, collapsible
  Generation details, and a catalog-driven shortcut guide improve dense review.

### Linux-aware playback

- **Balanced**, **Adaptive Motion**, **All Motion**, and **Static + Hover**
  provide explicit playback trade-offs.
- **All Motion** preserves uncapped visible motion instead of silently
  derating; it can consume substantial CPU and memory.
- Optional bounded 720p proxies can reduce decode pressure when native tooling
  is available, without modifying source media.

### Reliability, security, and testing

- Electron 43 and Node.js 22.12 establish the supported development/runtime
  toolchain.
- A sandboxed renderer, opaque range-capable local-media protocol, bounded IPC,
  authorized native paths, atomic profile settings, and coordinated shutdown
  harden the desktop boundary.
- Profile isolation, watcher ownership, media teardown, stale-request rejection,
  and destroyed-window shutdown behavior have dedicated regression coverage.
- The repository now gates zero-warning lint, Electron-ABI SQLite coverage,
  production Electron smoke tests, performance harnesses, and packaging.

## Upgrade notes

- Close VideoSwarm before upgrading. Because this is a large pre-1.0 storage
  and lifecycle update, release-candidate testers should back up irreplaceable
  application profile data first.
- Profile database evolution is additive and transactional. Existing tags,
  ratings, and review decisions are preserved.
- Existing rated-but-Unreviewed content is promoted to **Reviewed** to enforce
  the new review invariant; tags are never changed.
- Existing profiles begin without a saved review position. The first successful
  review/rating action or **Find Unreviewed** creates one.
- The first open of a root may build its persistent index. Later revisits use
  the cached first grid while checking for filesystem changes.

## Known limitations

- Linux NVIDIA hardware video decoding is not guaranteed by Electron/Chromium.
  Balanced or Static + Hover is recommended on CPU-bound systems.
- Codec support comes from Chromium; HEVC/H.265 may not decode everywhere.
- Embedded generation extraction currently requires a compatible system
  `ffprobe`. Exact adjacent JSON sidecars still work when embedded probing is
  unavailable.
- Arbitrary ComfyUI custom nodes and visual-workflow-only string composition
  may produce a transparent partial result rather than a guessed prompt.
- Copy Accepted is copy-only and does not transfer VideoSwarm metadata. Move
  Accepted remains deferred, and Reject processing is limited to 2,000 local
  files per scoped batch.
- Release artifacts currently target Windows x64 and Linux. Windows builds are
  unsigned, and there is no macOS, mobile, or web release.

## Release-candidate feedback

Follow the [v0.6 RC feedback tracker](https://github.com/Cerzi/videoswarm/issues/80)
for priority test areas and the stable-release gate. File each reproducible
problem through the [structured bug-report form](https://github.com/Cerzi/videoswarm/issues/new?template=bug_report.yml&labels=rc%20feedback)
so the operating system, CPU/GPU, folder size, codec/resolution, playback mode,
and diagnostics stay attached to the report.

Upgrade/profile retention, cold versus revisit loading, fullscreen audio
teardown, embedded metadata discovery, and Copy Accepted
collision/partial-result behavior are especially useful RC test areas.
